# ORA-01652: unable to extend temp segment by %s in tablespace %s

## Meaning

Temporary segment couldn't grow — TEMP tablespace full, or a permanent tablespace ran out during a sort/hash spill.

```
ORA-01652: unable to extend temp segment by 128 in tablespace TEMP
```

## Common Causes

- TEMP tablespace too small.
- Massive sort or hash join without adequate PGA workarea.
- Multiple concurrent big queries.
- Runaway query with cartesian product.
- Uncleaned temp segments from crashed sessions.

## Diagnostic Queries

```sql
-- Temp tablespace usage
SELECT   tablespace_name,
         ROUND(bytes_used/1024/1024/1024, 2) used_gb,
         ROUND(bytes_free/1024/1024/1024, 2) free_gb,
         ROUND(bytes_used*100/(bytes_used+bytes_free), 1) pct_used
FROM     v$temp_space_header
ORDER BY 4 DESC;

-- Sessions eating TEMP
SELECT   s.sid, s.username, s.sql_id,
         ROUND(su.blocks*ts.block_size/1024/1024, 2) mb,
         su.segtype
FROM     v$sort_usage su
JOIN     v$session s ON s.saddr = su.session_addr
JOIN     dba_tablespaces ts ON ts.tablespace_name = su.tablespace
ORDER BY 4 DESC;

-- SQL causing it (right now)
SELECT sql_id, sql_text FROM v$sql
WHERE  sql_id IN (SELECT sql_id FROM v$sort_usage);
```

## Fix

**Immediate — grow TEMP**:

```sql
ALTER TABLESPACE TEMP ADD TEMPFILE '/u01/oradata/PRD/temp02.dbf' SIZE 20G AUTOEXTEND ON MAXSIZE 50G;

-- Or extend existing
ALTER DATABASE TEMPFILE '/u01/oradata/PRD/temp01.dbf' AUTOEXTEND ON MAXSIZE 100G;
```

**Kill the offending session**:

```sql
ALTER SYSTEM KILL SESSION '150,32458' IMMEDIATE;
```

**Free stuck temp segments** (after crash):

```sql
ALTER TABLESPACE TEMP SHRINK SPACE KEEP 10G;
```

**Permanent tablespace ORA-01652**:

Yes — a large sort inside a permanent tablespace's temp segment (rare, mainly with `CREATE INDEX`, `CREATE TABLE AS SELECT`).

```sql
ALTER DATABASE DATAFILE '/u01/oradata/PRD/users01.dbf' RESIZE 100G;
ALTER TABLESPACE USERS ADD DATAFILE '/u01/oradata/PRD/users02.dbf' SIZE 50G AUTOEXTEND ON;
```

## Prevention

- TEMP sized 3x biggest expected sort.
- `PGA_AGGREGATE_TARGET` sized so smaller sorts stay in memory.
- Resource Manager cap on `TEMP` per group.
- Alert on TEMP % used.
- Watch `v$sort_usage` in long-running queries.
