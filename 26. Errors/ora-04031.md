# ORA-04031: unable to allocate %s bytes of shared memory ("%s","%s","%s","%s")

## Meaning

Shared pool (or other SGA component) couldn't allocate a chunk. Usually shared pool exhaustion or fragmentation.

```
ORA-04031: unable to allocate 4096 bytes of shared memory ("shared pool","SELECT ...","sga heap(1,0)","kglsim heap")
```

The last two args identify the sub-heap and allocation type.

## Common Causes

- Shared pool too small.
- SGA memory not making its way to the shared pool (ASMM oscillation).
- Bind variable non-use → each SQL takes shared-pool room.
- Very large PL/SQL packages loaded.
- Cursor leaks.
- Shared pool fragmentation from ASMM.

## Diagnostic Queries

```sql
-- Shared pool sizing
SELECT   pool, name, ROUND(bytes/1024/1024,2) mb
FROM     v$sgastat
WHERE    pool = 'shared pool'
ORDER BY bytes DESC
FETCH FIRST 20 ROWS ONLY;

-- Total shared pool free
SELECT   pool, name, ROUND(bytes/1024/1024,2) mb
FROM     v$sgastat WHERE name='free memory' AND pool='shared pool';

-- Free chunks by size
SELECT   ksmchcls, COUNT(*), ROUND(SUM(ksmchsiz)/1024/1024,2) mb
FROM     x$ksmsp
WHERE    ksmchcls = 'free'
GROUP BY ksmchcls;

-- Top SQL by shared-pool usage
SELECT   sql_id, executions, ROUND(sharable_mem/1024,2) sharable_kb,
         SUBSTR(sql_text,1,80)
FROM     v$sqlarea
ORDER BY sharable_mem DESC
FETCH FIRST 20 ROWS ONLY;

-- Objects in shared pool
SELECT   type, COUNT(*), ROUND(SUM(sharable_mem)/1024/1024,2) mb
FROM     v$db_object_cache
GROUP BY type
ORDER BY 3 DESC;
```

## Fix

**Immediate — free shared pool**:

```sql
ALTER SYSTEM FLUSH SHARED_POOL;
```

Temporary. If it recurs, permanent fix needed.

**Grow shared pool** (ASMM):

```sql
ALTER SYSTEM SET shared_pool_size = 6G SCOPE=BOTH;
```

Set as floor under ASMM to prevent MMAN from shrinking it.

**Set reserved pool**:

```sql
ALTER SYSTEM SET shared_pool_reserved_size = 500M SCOPE=BOTH;
```

Prevents small allocations from exhausting space needed for large ones.

**Application fix** — bind variables:

```sql
-- Check literals not using binds
SELECT   substr(sql_text,1,60), COUNT(*) copies
FROM     v$sqlarea
GROUP BY substr(sql_text,1,60)
HAVING   COUNT(*) > 100
ORDER BY 2 DESC;
```

`CURSOR_SHARING = FORCE` is a workaround, not a fix.

## Prevention

- Set `SHARED_POOL_SIZE` floor.
- Alert on shared pool % free < 5%.
- Enforce binds in application.
- Regularly review `V$SQLAREA` for literal explosion.
- Adequate SGA overall.
