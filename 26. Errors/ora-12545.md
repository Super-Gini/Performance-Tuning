# ORA-12545: Connect failed because target host or object does not exist

## Meaning

DNS lookup failed or the target IP/hostname didn't accept a TCP connection.

```
ORA-12545: Connect failed because target host or object does not exist
```

## Common Causes

- DNS name doesn't resolve.
- Host down / unreachable.
- Wrong hostname in TNS descriptor.
- IPv6 mishandling (server publishes IPv6 record, client only IPv4).
- SCAN listener returned an unreachable node IP.

## Diagnostic

Client side:

```bash
# Resolve
nslookup <host>
getent hosts <host>

# Reachable?
ping <host>
telnet <host> 1521

# TNS test
tnsping <alias>
```

Server:

```bash
# Listener bound to right interface?
lsnrctl status | grep HOST

# For SCAN
cluvfy comp scan
srvctl config scan
```

## Fix

**DNS**:

```bash
# Add to /etc/hosts as a workaround
echo "10.0.1.4 prd-db01 prd-db01.example.com" >> /etc/hosts
```

Long-term: fix DNS.

**Wrong hostname**:

Edit `tnsnames.ora` with correct value.

**SCAN listener directing to bad node**:

```bash
srvctl status listener -listener SCAN_LISTENER
crsctl status resource -t | grep -i scan
```

Restart if needed:

```bash
srvctl stop scan_listener
srvctl start scan_listener
```

**IPv6 issue**:

Force IPv4 in the JDBC URL or set `oracle.net.disableOob=true`.

## Prevention

- Reliable DNS with backups.
- SCAN listener HA well-configured.
- Consistent `/etc/hosts` across critical hosts.
- Test connections from every client subnet after network changes.
