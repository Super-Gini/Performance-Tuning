# ORA-01157: cannot identify/lock data file <n> - see DBWR trace file

## Meaning

DBWn can't open a datafile — usually filesystem or ASM problem.

```
ORA-01157: cannot identify/lock data file 5 - see DBWR trace file
ORA-01110: data file 5: '/u01/oradata/PRD/users01.dbf'
```

## Common Causes

- File missing on disk.
- File permissions wrong (Oracle user can't read).
- ASM diskgroup dismounted / disk offline.
- Filesystem unmounted.
- Storage error (bad LUN).
- File renamed at OS level but not in the DB.

## Diagnostic Queries

```sql
-- Which file is affected
SELECT file#, name, status, checkpoint_change#
FROM   v$datafile
WHERE  file# = &affected_file_id;

-- Check OS
!ls -la /u01/oradata/PRD/users01.dbf

-- File header
SELECT file#, name, status, tablespace_name FROM v$datafile_header
WHERE  file# = &affected_file_id;
```

## Fix

**File just missing / renamed** — put it back where the DB expects, or tell the DB where it moved:

```sql
STARTUP MOUNT;
ALTER DATABASE RENAME FILE '/old/path/users01.dbf' TO '/new/path/users01.dbf';
ALTER DATABASE OPEN;
```

**File really gone** — restore from RMAN:

```bash
rman target /
RMAN> STARTUP MOUNT;
RMAN> RESTORE DATAFILE 5;
RMAN> RECOVER DATAFILE 5;
RMAN> ALTER DATABASE OPEN;
```

**ASM disk offline** — mount:

```bash
sqlplus / as sysasm
ALTER DISKGROUP DATA MOUNT;
```

**Non-system datafile can be offlined to open the DB**:

```sql
ALTER DATABASE DATAFILE 5 OFFLINE;
ALTER DATABASE OPEN;
-- Then fix and recover
RMAN> RESTORE DATAFILE 5;
RMAN> RECOVER DATAFILE 5;
RMAN> ALTER DATABASE DATAFILE 5 ONLINE;
```

## Prevention

- Filesystem monitoring; alert on unmount.
- RMAN + FRA — always able to restore.
- Don't `rm` datafiles manually — use `DROP TABLESPACE ... INCLUDING CONTENTS AND DATAFILES`.
