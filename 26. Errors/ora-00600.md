# ORA-00600: internal error code, arguments: [...]

## Meaning

An **Oracle internal error** — a bug, or a symptom of corruption / resource exhaustion. The bracketed arguments identify the specific check that fired.

```
ORA-00600: internal error code, arguments: [kcbz_check_objd_typ], [], [], [], [], [], [], [], [], [], [], []
```

The first argument (`kcbz_check_objd_typ`) is the internal function name — search MOS by this string.

## Common Categories

- **Buffer cache** — `kcbz*`, `kcb*`.
- **Undo** — `ktubld*`, `ktbat*`.
- **Redo** — `kcr*`.
- **Optimizer / SQL** — `qcs*`, `qk*`.
- **Data dictionary** — `kkscls*`.
- **Block corruption** — `4194`, `4195`, `13013`.

Some are transient (a session died mid-operation); most are indicative of a bug or corruption.

## Diagnostic Queries

```sql
-- Recent ORA-00600 from alert log
SELECT originating_timestamp, message_text
FROM   v$diag_alert_ext
WHERE  message_text LIKE 'ORA-00600%'
   AND originating_timestamp > SYSDATE - 30
ORDER  BY originating_timestamp DESC;

-- Incident + trace file
SELECT incident_id, problem_key, error_facility, error_number, create_time
FROM   v$diag_incident
WHERE  problem_key LIKE '%ORA 600%'
   AND create_time > SYSDATE - 7
ORDER  BY create_time DESC;
```

Find the trace file via `V$DIAG_TRACE_FILE` or by looking in `.../incident/incdir_<n>/`.

## Fix

1. **Read the trace file** — has the call stack, SQL text, session state.
2. **Search MOS** — `ORA-00600 [kcbz_check_objd_typ]` — often a documented bug.
3. **Check corruption**:
   ```bash
   dbverify file=/u01/oradata/PRD/users01.dbf blocksize=8192
   ```
   Or:
   ```sql
   VALIDATE DATABASE;   -- RMAN
   SELECT * FROM v$database_block_corruption;
   ```
4. **Package the incident**:
   ```bash
   adrci
   adrci> ips create package incident <id>
   adrci> ips generate package <n> in /tmp
   ```
5. **Open MOS SR** with the ZIP.

## Immediate Actions

- **Doesn't repeat** — monitor and continue.
- **Repeats on the same object** — offline the object, restore or rebuild.
- **Repeats broadly** — instance may be corrupt; consider failover to standby.

## Prevention

- Stay current with RUs — many ORA-00600s get fixed in later RUs.
- Enable block change tracking + block media recovery.
- Enable `DB_LOST_WRITE_PROTECT=TYPICAL` on primary and standby.
- Regular DBVERIFY / `VALIDATE DATABASE` in RMAN.
