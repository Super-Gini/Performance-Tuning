# ORA-12514: TNS:listener does not currently know of service requested in connect descriptor

## Meaning

Connection reached the listener, but the listener doesn't have the requested `SERVICE_NAME` registered.

```
ORA-12514: TNS:listener does not currently know of service requested in connect descriptor
```

## Common Causes

- Instance is down (LREG never registered).
- Instance is starting (registration in progress).
- Wrong service name in TNS descriptor.
- `SERVICE_NAMES` init parameter mismatch.
- Case sensitivity in service name.
- Dynamic listener not receiving LREG registration.
- Wrong `LOCAL_LISTENER` / `REMOTE_LISTENER`.

## Diagnostic

Listener side:

```bash
lsnrctl status
lsnrctl services
```

Look for the service under "Services Summary". If absent, LREG hasn't registered.

Server side:

```sql
SHOW PARAMETER service_names
SHOW PARAMETER local_listener
SELECT name, network_name, con_id FROM v$services WHERE name NOT LIKE 'SYS$%';
```

## Fix

**Instance not registered** — force re-register:

```sql
ALTER SYSTEM REGISTER;
```

Confirm:

```bash
lsnrctl services
```

**Wrong `SERVICE_NAMES`**:

```sql
ALTER SYSTEM SET service_names = 'PRD,PRD_svc,PRD_ro' SCOPE=BOTH;
ALTER SYSTEM REGISTER;
```

**Wrong `LOCAL_LISTENER`**:

```sql
-- Point at correct listener (host:port)
ALTER SYSTEM SET local_listener = '(ADDRESS=(PROTOCOL=TCP)(HOST=prd-db01)(PORT=1521))' SCOPE=BOTH;
ALTER SYSTEM REGISTER;
```

**Client side — connect string uses wrong service**:

Fix the `SERVICE_NAME` in `tnsnames.ora` or in the URL to match what's registered.

**PDB service**:

For a PDB, ensure the PDB is open and its service is registered:

```sql
ALTER PLUGGABLE DATABASE PDB1 OPEN;
ALTER SESSION SET CONTAINER = PDB1;
EXEC DBMS_SERVICE.START_SERVICE('PDB1');
ALTER SYSTEM REGISTER;
```

## Prevention

- Startup scripts: after `STARTUP`, `ALTER SYSTEM REGISTER;`.
- Save PDB state so services come back after CDB restart:
  ```sql
  ALTER PLUGGABLE DATABASE PDB1 SAVE STATE;
  ```
- Consistent service naming across environments.
