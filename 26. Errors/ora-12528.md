# ORA-12528: TNS:listener: all appropriate instances are blocking new connections

## Meaning

The listener knows about the instance, but it's registered as "blocked" — new connections refused. Common while instance is starting up or `STARTUP RESTRICT` is in effect.

```
ORA-12528: TNS:listener: all appropriate instances are blocking new connections
```

## Common Causes

- Instance is in `STARTUP RESTRICT` mode.
- Instance startup in progress (very brief).
- `RESOURCE_MANAGER_PLAN` capping active sessions.
- Instance is `QUIESCED` (`ALTER SYSTEM QUIESCE RESTRICTED`).
- Instance shutting down.

## Diagnostic

```sql
-- Login mode
SELECT logins, active_state, database_status, shutdown_pending FROM v$instance;

-- Restricted?
SELECT logins FROM v$instance;   -- 'RESTRICTED' or 'ALLOWED'

-- If RESTRICT, you can still connect as SYSDBA locally
```

Listener side:

```bash
lsnrctl services
# Look for BLOCKED status on the service line
```

## Fix

**Disable restricted session**:

```sql
ALTER SYSTEM DISABLE RESTRICTED SESSION;
```

**Instance was quiesced**:

```sql
ALTER SYSTEM UNQUIESCE;
```

**Wait for startup** — a moment after `STARTUP` regular users can log in.

**Startup was `STARTUP RESTRICT` intentional** — connect with `RESTRICTED SESSION` privilege:

```sql
GRANT RESTRICTED SESSION TO app_dba;
```

**Instance shutting down** — abort/wait.

## Prevention

- Startup scripts avoid `RESTRICT` unless you need it.
- Communicate maintenance windows.
- Monitor `v$instance.logins` in your alerting.
