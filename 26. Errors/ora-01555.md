# ORA-01555: snapshot too old: rollback segment number %s with name "%s" too small

## Meaning

A long-running query needs pre-image undo that has been overwritten. Read-consistent snapshot cannot be constructed.

```
ORA-01555: snapshot too old: rollback segment number %s with name "%s" too small
```

## Common Causes

- Long-running query on a heavily-updated table.
- Undo tablespace too small for retention.
- `UNDO_RETENTION` too low.
- Delayed block cleanout on scanned blocks.
- LOB storage — `RETENTION` on LOB inadequate.
- Fetch across commits (application anti-pattern).

## Diagnostic Queries

```sql
-- Recent occurrences from undo stats
SELECT begin_time, end_time, ssolderrcnt, maxquerylen, maxquerysqlid
FROM   v$undostat
WHERE  ssolderrcnt > 0
ORDER  BY begin_time DESC
FETCH  FIRST 20 ROWS ONLY;

-- Longest query today
SELECT MAX(maxquerylen) longest_query_secs
FROM   v$undostat
WHERE  begin_time > SYSDATE - 1;

-- Recommended sizing
SELECT   MAX(undoblks) * (SELECT block_size FROM dba_tablespaces
                          WHERE tablespace_name = (SELECT value FROM v$parameter
                                                   WHERE name='undo_tablespace'))/1024/1024 mb_10min,
         MAX(maxquerylen) max_query_secs,
         MAX(tuned_undoretention) tuned_retention_secs
FROM     v$undostat;
```

## Fix

**Bump retention + tablespace**:

```sql
ALTER SYSTEM SET undo_retention = 10800 SCOPE=BOTH;   -- 3 hours

-- Guarantee retention (may cause ORA-30036 undo full)
ALTER TABLESPACE UNDOTBS1 RETENTION GUARANTEE;

-- Grow undo tablespace
ALTER DATABASE DATAFILE '+DATA/PRD/undotbs01.dbf' RESIZE 50G;
```

**Delayed block cleanout on the source** — commit-cleanout after big load:

```sql
-- Force cleanout on the target table
SELECT /*+ FULL(t) */ COUNT(*) FROM T t;
```

**For LOB ORA-01555** — the LOB SEGMENT'S retention (not undo):

```sql
ALTER TABLE t MODIFY LOB (data) (RETENTION);
-- or
ALTER TABLE t MODIFY LOB (data) (PCTVERSION 30);
```

**Fetch across commits — application fix**:

```plsql
-- BAD
FOR r IN (SELECT * FROM big_t) LOOP
  UPDATE big_t SET ... WHERE ROWID = r.ROWID;
  COMMIT;   -- causes ORA-01555 on the OPEN CURSOR
END LOOP;

-- BETTER
DECLARE
  n NUMBER := 0;
BEGIN
  FOR r IN (SELECT ROWID FROM big_t) LOOP
    UPDATE big_t SET ... WHERE ROWID = r.ROWID;
    n := n + 1;
    IF MOD(n, 1000) = 0 THEN COMMIT; END IF;
  END LOOP;
  COMMIT;
END;
/
```

## Prevention

- Size undo tablespace for peak (see [Undo Parameters](../25-reference/initialization-parameters/undo-parameters.md)).
- `RETENTION GUARANTEE` on databases with big reporting queries.
- Schedule big reports off-peak.
- Cardinality-aware LOB `RETENTION`.
- Avoid fetch-across-commits.
