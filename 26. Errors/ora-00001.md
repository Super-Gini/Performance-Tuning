# ORA-00001: unique constraint violated

## Meaning

An `INSERT` or `UPDATE` tried to create a duplicate value in a column that has a UNIQUE constraint or PRIMARY KEY.

Full message:

```
ORA-00001: unique constraint (<owner>.<constraint>) violated
```

## Common Causes

- Retry logic re-inserting after a network glitch.
- Missing coordination between concurrent writers.
- Sequence out of sync with an existing PK (post-migration, post-import).
- Wrong data — same "unique" key present multiple times in the source.
- UPSERT logic that wasn't atomic.

## Diagnostic Queries

```sql
-- Which constraint fired
-- The ORA-00001 message includes the constraint name; look it up:
SELECT owner, constraint_name, table_name, constraint_type, search_condition
FROM   dba_constraints
WHERE  constraint_name = '&constraint_name';

-- Duplicate rows (assuming column X, table T)
SELECT X, COUNT(*) FROM T GROUP BY X HAVING COUNT(*) > 1;

-- Sequence sync (if PK from sequence)
SELECT last_number FROM dba_sequences WHERE sequence_name = 'SEQ_ORDER_ID';
SELECT MAX(id) FROM ORDERS;
```

## Fix

Immediate (specific INSERT):

```sql
-- Adjust sequence
DECLARE
  v_max NUMBER; v_curr NUMBER; v_inc NUMBER;
BEGIN
  SELECT MAX(id) INTO v_max FROM orders;
  SELECT last_number INTO v_curr FROM dba_sequences WHERE sequence_name='SEQ_ORDER_ID';
  v_inc := v_max + 1000 - v_curr;
  EXECUTE IMMEDIATE 'ALTER SEQUENCE seq_order_id INCREMENT BY '||v_inc;
  EXECUTE IMMEDIATE 'SELECT seq_order_id.NEXTVAL FROM dual';
  EXECUTE IMMEDIATE 'ALTER SEQUENCE seq_order_id INCREMENT BY 1';
END;
/
```

Deduplicate rows (be careful):

```sql
DELETE FROM T WHERE ROWID NOT IN
   (SELECT MIN(ROWID) FROM T GROUP BY X);
```

## Prevention

- Use MERGE / INSERT with ON CONFLICT semantics for idempotent inserts.
- Session-safe retries (check for existence before insert).
- After every Data Pump import that carries PK data, resync the sequence.
