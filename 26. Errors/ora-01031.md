# ORA-01031: insufficient privileges

## Meaning

The user tried to execute an operation without a required grant.

```
ORA-01031: insufficient privileges
```

## Common Causes

- Missing system privilege (`CREATE TABLE`, `CREATE PROCEDURE`, etc.).
- Missing object privilege (`SELECT`, `EXECUTE`).
- Attempting `AS SYSDBA` without password file entry.
- PL/SQL definer's rights not honoring role-based privs (a common gotcha).
- `PUBLIC` grant revoked.
- CDB/PDB confusion — granted in wrong container.

## Diagnostic Queries

```sql
-- System privileges of a user
SELECT privilege, admin_option FROM dba_sys_privs
WHERE  grantee = 'APP' ORDER BY privilege;

-- Object privileges
SELECT owner, table_name, privilege, grantable
FROM   dba_tab_privs WHERE grantee = 'APP' ORDER BY owner, table_name;

-- Role membership
SELECT granted_role, admin_option, default_role
FROM   dba_role_privs WHERE grantee = 'APP' ORDER BY granted_role;

-- What roles bring you privileges
SELECT r.role, sp.privilege FROM dba_role_privs rp
JOIN   role_sys_privs sp ON sp.role = rp.granted_role
JOIN   dba_roles r ON r.role = rp.granted_role
WHERE  rp.grantee = 'APP';

-- Current session privileges (from the session itself)
SELECT * FROM session_privs;
SELECT * FROM session_roles;
```

## Fix

**Grant the missing privilege**:

```sql
GRANT SELECT ON hr.employees TO app;
GRANT CREATE TABLE TO app;
GRANT DBA TO app;   -- rare; usually don't
```

**Definer's rights PL/SQL**: role-based privileges are NOT active in PL/SQL blocks compiled as definer's rights. Use direct grants:

```sql
GRANT SELECT ON hr.employees TO app_pkg_owner;   -- not through a role
```

Or convert to invoker's rights:

```sql
CREATE OR REPLACE PROCEDURE p AUTHID CURRENT_USER AS
BEGIN
   -- role-based grants now work
END;
/
```

**SYSDBA remote logon**:

```bash
# Add to password file
orapwd file=$ORACLE_HOME/dbs/orapwPRD password=<sys_pw> entries=10 format=12
```

Grant SYSDBA:

```sql
GRANT SYSDBA TO app_dba;
```

**CDB/PDB mix-up**:

```sql
ALTER SESSION SET CONTAINER = PDB1;
GRANT SELECT ON app.orders TO reporting;
```

## Prevention

- Least-privilege model.
- Grant to roles for interactive users; grant directly for stored code.
- Regular privilege audit — `dba_sys_privs`, `dba_tab_privs` snapshots.
- Version-control the grants.
