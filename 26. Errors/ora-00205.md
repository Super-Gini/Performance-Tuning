# ORA-00205: error in identifying control file, check alert log for more info

## Meaning

`STARTUP MOUNT` cannot access one of the control files listed in `CONTROL_FILES`.

## Common Causes

- Control file path wrong in spfile/pfile.
- Missing / renamed / permissions-broken control file on disk.
- ASM diskgroup dismounted.
- Wrong `ORACLE_HOME` (wrong instance's spfile picked up).

## Diagnostic Queries

Before startup:

```bash
# Filesystem
ls -la /u01/oradata/PRD/control01.ctl
ls -la /u02/fast_recovery_area/PRD/control02.ctl

# ASM
asmcmd
ASMCMD> ls +DATA/PRD/controlfile/
```

Alert log will say which file is missing:

```
ORA-00202: control file: '/u01/oradata/PRD/control01.ctl'
ORA-27041: unable to open file
Linux-x86_64 Error: 2: No such file or directory
```

## Fix

**One control file missing, others OK** — restore from surviving copy:

```bash
# Copy a good one
cp /u02/fast_recovery_area/PRD/control02.ctl /u01/oradata/PRD/control01.ctl

# Or use ASM
asmcmd
ASMCMD> cp +DATA/PRD/controlfile/current.ctl +DATA/PRD/controlfile/current_copy.ctl
```

Then start:

```sql
STARTUP MOUNT;
ALTER DATABASE OPEN;
```

**All control files gone** — restore from RMAN:

```bash
rman target /
RMAN> STARTUP NOMOUNT;
RMAN> RESTORE CONTROLFILE FROM AUTOBACKUP;
RMAN> ALTER DATABASE MOUNT;
RMAN> RECOVER DATABASE;
RMAN> ALTER DATABASE OPEN RESETLOGS;
```

**Wrong `CONTROL_FILES` in spfile** — edit pfile, restart:

```sql
CREATE PFILE FROM SPFILE;
-- edit init<SID>.ora, fix control_files=('...','...')
STARTUP PFILE='/tmp/initPRD.ora' MOUNT;
CREATE SPFILE FROM PFILE = '/tmp/initPRD.ora';
```

## Prevention

- **Multiplex control files** on separate storage (2–3 copies).
- Include control files in RMAN autobackup:
  ```sql
  CONFIGURE CONTROLFILE AUTOBACKUP ON;
  ```
- Alert on `V$DATABASE.CONTROLFILE_TYPE` or file-existence checks.
