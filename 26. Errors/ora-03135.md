# ORA-03135: connection lost contact

## Meaning

The client detected the connection to the server is broken — but unlike ORA-03113, the server process wasn't necessarily observed dying. The connection just stopped responding.

```
ORA-03135: connection lost contact
```

## Common Causes

- Firewall/load-balancer dropped an idle session.
- Server host network flap.
- Instance restart between calls.
- Client-side TCP timeout (`SQLNET.EXPIRE_TIME`).
- Session killed by `ALTER SYSTEM KILL SESSION`.
- Resource Manager `CANCEL_SQL` or `KILL_SESSION`.

## Diagnostic Queries

```sql
-- Session killed events
SELECT   originating_timestamp, message_text
FROM     v$diag_alert_ext
WHERE    message_text LIKE '%kill%' OR message_text LIKE '%disconnect%'
   AND   originating_timestamp > SYSDATE - 1/24
ORDER BY originating_timestamp DESC;

-- Recent instance restart?
SELECT startup_time FROM v$instance;

-- LREG showing services normal?
!lsnrctl status
```

Network side:

```bash
# Firewall session timeout typical 30-60 minutes idle
# Check with the security team

# Test TCP path from client
telnet <db_host> 1521
```

## Fix

**Reconnect and retry** — usually adequate.

**Firewall idle timeout**:

Client sqlnet.ora:

```
SQLNET.EXPIRE_TIME=1     # send keepalive every 1 minute
```

Server sqlnet.ora:

```
SQLNET.EXPIRE_TIME=1
```

Or shorter than firewall's idle timeout.

**Session was killed**:

```sql
-- Correlate to alert log
```

**Instance restart** — normal after planned bounce.

**Resource Manager cancellation**:

Check `SWITCH_GROUP` / `CANCEL_SQL` settings in the active plan.

## Prevention

- Set `SQLNET.EXPIRE_TIME` on both sides (< firewall idle).
- Application connection pool validation queries (e.g., HikariCP `connection-test-query`).
- Application retry logic on ORA-03135.
