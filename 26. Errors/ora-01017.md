# ORA-01017: invalid username/password; logon denied

## Meaning

Authentication failed.

```
ORA-01017: invalid username/password; logon denied
```

## Common Causes

- Wrong password.
- Case sensitivity — `SEC_CASE_SENSITIVE_LOGON = TRUE` in 11g+.
- Account locked or expired (may surface as ORA-28000/28001 but occasionally as ORA-01017).
- Password profile changed (`PASSWORD_LOGIN_ATTEMPTS`).
- Wrong DB (client points at different instance).
- Password expired but grace period ended.
- Password verification function rejected new password format.
- `pwfile` corrupted (for `SYSDBA` remote logon).

## Diagnostic Queries

```sql
-- Account status
SELECT username, account_status, lock_date, expiry_date, profile, last_login
FROM   dba_users
WHERE  username = UPPER('&user');

-- Password versions (10G/11G/12C)
SELECT username, password_versions FROM dba_users WHERE username = UPPER('&user');

-- Case sensitivity setting
SHOW PARAMETER sec_case_sensitive_logon
SHOW PARAMETER allowed_logon_version_server
```

## Fix

**Unknown password**:

```sql
ALTER USER app IDENTIFIED BY "NewPassword2026!";
```

**Locked** (from too many failed attempts):

```sql
ALTER USER app ACCOUNT UNLOCK;
```

**Expired**:

```sql
ALTER USER app IDENTIFIED BY "NewPassword2026!";
-- Or if grace period still open:
ALTER USER app PASSWORD EXPIRE;   -- forces reset
```

**Only 10G hash present, driver requires 11G/12C**:

Client older than server or vice versa — 10G hash is not returned to modern clients when `SEC_CASE_SENSITIVE_LOGON=TRUE`.

```sql
-- Regenerate password to add current version
ALTER USER app IDENTIFIED BY "&pw";
```

**SYSDBA remote logon fails but local `/ as sysdba` works** — password file issue:

```bash
orapwd file=$ORACLE_HOME/dbs/orapwPRD password=<sys_pw> entries=10 format=12
```

## Prevention

- Password rotation via automation.
- Alert on `dba_users.account_status <> 'OPEN'`.
- Consistent client and server versions.
- SSO / Kerberos to avoid password sprawl.
