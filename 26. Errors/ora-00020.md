# ORA-00020: maximum number of processes exceeded

## Meaning

The database has as many OS processes as `PROCESSES` allows. New connections get:

```
ORA-00020: maximum number of processes (%s) exceeded
```

`PROCESSES` = max OS processes attached to the instance (background + foreground). Every session needs a process.

## Common Causes

- Application connection pool leak.
- Sudden spike (batch, mass logon).
- `PROCESSES` too low for the app.
- A hung session refusing to die — piles up retries.

## Diagnostic Queries

```sql
-- Current usage
SELECT resource_name, current_utilization, max_utilization, limit_value
FROM   v$resource_limit
WHERE  resource_name IN ('processes','sessions');

-- Process counts by program
SELECT program, COUNT(*) FROM v$session GROUP BY program ORDER BY 2 DESC;

-- Idle sessions consuming a process
SELECT sid, serial#, username, program, machine, status, last_call_et/60 mins_idle
FROM   v$session
WHERE  status = 'INACTIVE' AND type = 'USER'
ORDER  BY last_call_et DESC
FETCH  FIRST 30 ROWS ONLY;
```

## Fix

**Immediate** (get connections working):

```sql
-- Kill idle sessions > N minutes
BEGIN
  FOR r IN (
    SELECT sid, serial# FROM v$session
    WHERE  status='INACTIVE' AND type='USER'
       AND last_call_et > 1800
  ) LOOP
    EXECUTE IMMEDIATE 'ALTER SYSTEM KILL SESSION '''||r.sid||','||r.serial#||''' IMMEDIATE';
  END LOOP;
END;
/
```

Bump the limit (bounce required):

```sql
ALTER SYSTEM SET processes = 2000 SCOPE=SPFILE;
ALTER SYSTEM SET sessions = 3000 SCOPE=SPFILE;   -- ~1.5x processes
-- Bounce
```

## Prevention

- Sizing: `PROCESSES` should be at least `pool_size × app_instances × 1.5` + 100 baseline.
- Idle session timeout in profile (`IDLE_TIME`).
- Application pool `max` less than `PROCESSES - 100`.
- Alert when `v$resource_limit.current_utilization` > 80%.
