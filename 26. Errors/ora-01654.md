# ORA-01654: unable to extend index %s.%s by %s in tablespace %s

## Meaning

Same as ORA-01653 but for an index. Tablespace can't grow to accommodate more index blocks.

```
ORA-01654: unable to extend index APP.PK_ORDERS by 128 in tablespace USERS_IDX
```

## Common Causes

- Same as [ORA-01653](ora-01653.md).
- Sometimes bulk INSERT rebuilds much of an index — extra space needed transiently.

## Diagnostic Queries

Same as ORA-01653; substitute the index's tablespace. If the index has its own tablespace:

```sql
-- Index -> tablespace
SELECT   index_name, tablespace_name
FROM     dba_indexes
WHERE    index_name = '&index_name' AND owner = '&owner';

-- If the index was created without explicit tablespace, it goes to owner's default TS
SELECT default_tablespace FROM dba_users WHERE username = '&owner';
```

## Fix

Same options as ORA-01653: extend/add datafile, autoextend, user quota.

**Rebuild the index** — sometimes it just needs freshening (especially after mass DELETE):

```sql
ALTER INDEX app.pk_orders REBUILD ONLINE TABLESPACE users_idx;
-- Or COALESCE (less invasive)
ALTER INDEX app.pk_orders COALESCE;
```

**Move index to a bigger TS**:

```sql
ALTER INDEX app.pk_orders REBUILD ONLINE TABLESPACE users_idx_big;
```

## Prevention

- Separate index tablespaces sized 30% of table tablespace.
- Rebuild noisy indexes quarterly.
- Autoextend on all datafiles.
