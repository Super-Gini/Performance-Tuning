# ORA-12154: TNS:could not resolve the connect identifier specified

## Meaning

The client couldn't map the connect string to a network descriptor.

```
ORA-12154: TNS:could not resolve the connect identifier specified
```

## Common Causes

- Alias not present in `tnsnames.ora`.
- Wrong `TNS_ADMIN` (client looking at wrong file).
- Typo in alias.
- LDAP not configured / OID unreachable.
- `sqlnet.ora` `NAMES.DIRECTORY_PATH` wrong.
- Easy Connect syntax error (`host:port/service`).

## Diagnostic

Show the environment client sees:

```bash
env | grep -E 'ORACLE_HOME|TNS_ADMIN|LD_LIBRARY_PATH'
which sqlplus
tnsping <alias>
```

Test:

```bash
tnsping PRD
# TNS-03502 = alias not found
# TNS-12154 = same
```

Check the file:

```bash
cat $TNS_ADMIN/tnsnames.ora | grep -i <alias>
```

## Fix

**Add / correct the alias**:

```
PRD =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = prd-db01.example.com)(PORT = 1521))
    (CONNECT_DATA =
      (SERVER = DEDICATED)
      (SERVICE_NAME = PRD_svc)
    )
  )
```

**Use Easy Connect**:

```bash
sqlplus app/pw@//prd-db01.example.com:1521/PRD_svc
```

Enable in `sqlnet.ora`:

```
NAMES.DIRECTORY_PATH = (TNSNAMES, EZCONNECT)
```

**Set TNS_ADMIN**:

```bash
export TNS_ADMIN=/etc/oracle
```

## Prevention

- Standard `TNS_ADMIN` location across all clients.
- Automate `tnsnames.ora` distribution.
- Prefer LDAP (OID/AD) for enterprise setups.
- Use consistent aliases in code and configs.
