# ORA-07445: exception encountered: core dump [%s]

## Meaning

A **segmentation fault / access violation** in an Oracle process. The bracketed argument is the function where the SIGSEGV happened.

```
ORA-07445: exception encountered: core dump [kglobpn()+51] [SIGSEGV] [ADDR:0x0] [PC:0x1234] [Address not mapped to object] []
```

Similar workflow to [ORA-00600](ora-00600.md): usually a bug or corruption.

## Common Causes

- Bug in Oracle code (specific function reachable via specific SQL).
- Bad memory (rare) — ECC failure.
- Wrong PL/SQL native compile.
- OS library mismatch.
- SGA corruption.
- Very rarely, a bad user PL/SQL call into `DBMS_STATS` etc.

## Diagnostic Queries

Same as ORA-00600:

```sql
-- Recent
SELECT originating_timestamp, message_text
FROM   v$diag_alert_ext
WHERE  message_text LIKE 'ORA-07445%'
  AND  originating_timestamp > SYSDATE - 30
ORDER  BY originating_timestamp DESC;

-- Incidents
SELECT incident_id, problem_key, error_facility, create_time
FROM   v$diag_incident
WHERE  problem_key LIKE '%ORA 7445%'
  AND  create_time > SYSDATE - 30
ORDER  BY create_time DESC;
```

## Fix

1. **Read the trace file** — call stack, arguments, SQL context.
2. **Search MOS** — the function name in brackets:
   `ORA-07445 kglobpn+51`
3. **Search for a fix in a later RU** — very common; Oracle backports.
4. **Apply the fix** or the recommended workaround.
5. **Package for SR**:
   ```bash
   adrci exec="ips create package incident <id>"
   adrci exec="ips generate package <n> in /tmp"
   ```

## Prevention

- Stay current with RUs.
- Enable ECC memory on the DB host.
- Enable memory corruption detection (`_disable_kcgshu_uadler=FALSE` etc. — support-guided).
- Regular block validation via RMAN `VALIDATE`.
