# ORA-12516: TNS: listener could not find matching protocol stack

## Overview

Listener knows the service but cannot find a matching **handler** for the requested protocol / connection mode. Historically also seen as **"listener could not find handler with matching protocol stack"**. Under high concurrency this variant appears alongside `ORA-12519` and `ORA-12520` when the instance's `PROCESSES` cap or shared server pool is exhausted.

## Common Causes

1. **`PROCESSES` cap reached** — no free slots.
2. **All shared servers busy** — shared server pool exhausted.
3. **`SESSIONS` cap reached** — same effect via sessions parameter.
4. **Listener registered handler doesn't match client's protocol** (rare).
5. **Restricted session mode** on instance rejecting non-privileged connects.

## Diagnostic Steps

### 1. Check current resource use

```sql
SELECT resource_name, current_utilization, max_utilization,
       initial_allocation, limit_value
FROM   v$resource_limit
WHERE  resource_name IN ('processes','sessions','shared_servers','dispatchers');
```

If `current_utilization` = `limit_value`, you're at cap.

### 2. Check for restricted session

```sql
SELECT logins FROM v$instance;  -- ALLOWED or RESTRICTED
```

If RESTRICTED, only users with RESTRICTED SESSION privilege can connect.

### 3. Listener side

```bash
lsnrctl services
# Shows how many handlers each service has
```

### 4. Alert log

Look for `WARNING: inbound connection timed out` or `Process X died, see its trace file`.

## Common Fixes

### PROCESSES cap

```sql
SHOW PARAMETER processes
-- Bounce required to change
ALTER SYSTEM SET processes = 800 SCOPE = SPFILE;
```

**Immediate mitigation**: kill idle sessions.

```sql
SELECT sid, serial#, username, machine, last_call_et
FROM   v$session
WHERE  status = 'INACTIVE'
   AND last_call_et > 3600
ORDER  BY last_call_et DESC;

-- Kill one
ALTER SYSTEM KILL SESSION '<sid>,<serial#>' IMMEDIATE;
```

### Shared server exhausted

```sql
ALTER SYSTEM SET max_shared_servers = 40 SCOPE=BOTH;
```

Or force dedicated:

```
SERVER=DEDICATED
```

### Restricted session

```sql
ALTER SYSTEM DISABLE RESTRICTED SESSION;
```

## Best Practices

1. Size `processes` at peak concurrent + 30% headroom.
2. Use **application-tier connection pooling** to bound connection count.
3. Configure `SQLNET.EXPIRE_TIME = 10` — clean up dead sessions.
4. Use Resource Manager to limit long-idle sessions.
5. Alert on `V$RESOURCE_LIMIT` approaching cap.
6. Force `SERVER=DEDICATED` for admin / RMAN sessions.

## Interview Questions

1. **Q:** Common cause of `ORA-12516`?
   **A:** `PROCESSES` cap reached, or all shared servers busy.

2. **Q:** How do you check?
   **A:** `V$RESOURCE_LIMIT`.

3. **Q:** Immediate mitigation without restart?
   **A:** Kill idle sessions.

4. **Q:** Permanent fix?
   **A:** Increase `processes` (needs restart), fix app connection leak, use connection pool.

5. **Q:** What is restricted session mode?
   **A:** Instance allows only sessions with RESTRICTED SESSION privilege.
