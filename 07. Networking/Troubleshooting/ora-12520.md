# ORA-12520: TNS: listener could not find available handler for requested type

## Overview

Client asked for a specific server type (DEDICATED or SHARED) and the listener has no matching handler available. Related to `ORA-12516`/`ORA-12519` but pinpoints a **type mismatch**.

## Common Causes

1. Client asked `SERVER=SHARED` but shared server not configured.
2. Client asked `SERVER=DEDICATED` but all `PROCESSES` slots busy.
3. All shared servers busy and client's request cannot be queued.
4. `DEDICATED_THROUGH_BROKER_LISTENER=ON` misconfiguration.

## Diagnostic Steps

### 1. Connect string

```
(CONNECT_DATA = (SERVICE_NAME = prod)(SERVER = SHARED))
```

Was SHARED requested?

### 2. Instance shared server config

```sql
SHOW PARAMETER shared_servers
SHOW PARAMETER dispatchers
```

If both are 0/empty, no shared server available → clients requesting SHARED will fail.

### 3. Listener handlers

```bash
lsnrctl services
```

Look for lines like `Handler(s):` under each service. Should show `DEDICATED` and possibly `DISPATCHER`.

## Common Fixes

### Client wants SHARED but not configured

Change to DEDICATED:

```
SERVER=DEDICATED
```

Or configure shared server on instance:

```sql
ALTER SYSTEM SET dispatchers = '(PROTOCOL=TCP)(DISPATCHERS=2)' SCOPE=BOTH;
ALTER SYSTEM SET shared_servers = 4;
```

### DEDICATED at cap

Kill idle sessions, increase `processes`.

### Enable dedicated-through-broker

For DRCP (Database Resident Connection Pool) contexts, sometimes handler advertisement requires:

```
DEDICATED_THROUGH_BROKER_LISTENER=ON
```

in `listener.ora`.

## Best Practices

1. Default to **dedicated** unless there's a specific reason.
2. If shared server is enabled, size dispatchers and shared servers per workload.
3. Alert on connection failures — indicates capacity issues.
4. Standardize on `SERVER=DEDICATED` in TNS for critical apps.

## Interview Questions

1. **Q:** `ORA-12520` — cause?
   **A:** Listener has no handler for the requested `SERVER` type (DEDICATED or SHARED).

2. **Q:** Common fix?
   **A:** Match client's `SERVER=` value to what the instance is configured for; or fix capacity.

3. **Q:** Do you need shared server today?
   **A:** Rarely. Use dedicated + connection pooling; consider DRCP for high-connection-count web apps.
