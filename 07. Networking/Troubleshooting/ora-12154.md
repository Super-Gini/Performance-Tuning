# ORA-12154: TNS: could not resolve the connect identifier

## Overview

The client cannot resolve the connect string (alias) to a network address + service. This is purely a client-side name resolution failure — it means the client never actually tried to reach the database. Fix on the client, not the server.

## Common Causes

1. **Alias missing from `tnsnames.ora`** — no matching entry.
2. **Wrong `tnsnames.ora`** — client looking at a different file than you edited (`TNS_ADMIN`).
3. **Alias present but syntax error** — mis-parsed by client.
4. **`sqlnet.ora` `NAMES.DIRECTORY_PATH`** — TNSNAMES not in the list.
5. **Multi-tier confusion** — App server has its own `tnsnames.ora`.
6. **Case mismatch (rare)** — usually not case-sensitive.
7. **Windows GUI tools** — sometimes ignore `TNS_ADMIN`.

## Diagnostic Steps

### 1. Verify TNS_ADMIN

```bash
# Linux
echo $TNS_ADMIN
ls -la $TNS_ADMIN/tnsnames.ora

# Windows
set TNS_ADMIN
```

If unset, Oracle uses `$ORACLE_HOME/network/admin`.

### 2. Verify the alias exists

```bash
grep -A5 "^PROD" $TNS_ADMIN/tnsnames.ora
```

### 3. Test with `tnsping`

```bash
tnsping PROD
# should print used parameters file and description
```

Success = alias resolves. Failure = same `ORA-12154`.

### 4. Check `sqlnet.ora`

```bash
grep DIRECTORY_PATH $TNS_ADMIN/sqlnet.ora
```

Should include `TNSNAMES`:

```
NAMES.DIRECTORY_PATH = (TNSNAMES, EZCONNECT)
```

### 5. Try EZCONNECT to bypass tnsnames.ora

```bash
sqlplus hr/pwd@//dbhost:1521/prod.corp.example.com
```

If this works, the problem is confined to `tnsnames.ora` resolution.

## Common Fixes

### Missing alias

Add to `tnsnames.ora`:

```
PROD =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = dbhost)(PORT = 1521))
    (CONNECT_DATA = (SERVICE_NAME = prod.corp.example.com)))
```

### Wrong TNS_ADMIN

Set explicitly:

```bash
export TNS_ADMIN=/etc/oracle
sqlplus hr/pwd@PROD
```

For app servers, set in the environment configuration (WebLogic `startWebLogic.sh`, systemd unit, etc.).

### Bad syntax

Common mistakes:

- Missing parenthesis
- Wrong keyword (`SERVICE_NAM =`)
- Trailing spaces in the alias name
- BOM byte in file (Windows Notepad)

Validate with `tnsping`.

### NAMES.DIRECTORY_PATH doesn't include TNSNAMES

Fix `sqlnet.ora`:

```
NAMES.DIRECTORY_PATH = (TNSNAMES, EZCONNECT, LDAP)
```

### Multi-tier

Each tier has its own `tnsnames.ora`. Distribute via config management (Ansible, Puppet, Chef).

## Best Practices

1. **Centralize** `tnsnames.ora` distribution via config management.
2. **Use LDAP** name resolution in large environments — no per-client files.
3. **EZCONNECT** for tools and admin — no `tnsnames.ora` needed.
4. Test every new alias with `tnsping`.
5. For Windows apps: verify `TNS_ADMIN` in registry (`HKLM\SOFTWARE\ORACLE\KEY_<home>`) not just environment.

## Interview Questions

1. **Q:** What does `ORA-12154` mean?
   **A:** Client cannot resolve the connect string to a network descriptor. Purely name resolution.

2. **Q:** Client or server issue?
   **A:** Client — server was never contacted.

3. **Q:** How do you test resolution?
   **A:** `tnsping <alias>`.

4. **Q:** How do you bypass tnsnames.ora?
   **A:** EZCONNECT: `//host:port/service`.

5. **Q:** Where does the client look for tnsnames.ora?
   **A:** `TNS_ADMIN` if set; else `$ORACLE_HOME/network/admin`.
