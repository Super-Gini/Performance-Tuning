# ORA-12514: TNS: listener does not currently know of service

## Overview

Client connected to the listener but requested a service the listener doesn't currently have registered. This is one of the most common Oracle networking errors.

## Common Causes

1. **Service name typo** in connect string.
2. **Instance not yet registered** (just restarted, LREG hasn't fired).
3. **Instance registered with different service name** than requested.
4. **PDB not open** — closed PDBs deregister their service.
5. **Instance registered with a different listener**.
6. **RAC service not started** on any instance.

## Diagnostic Steps

### 1. What services does the listener have?

```bash
lsnrctl services
```

Look for the exact service name your client uses.

### 2. Client-side connect string

```bash
grep -A5 PROD $TNS_ADMIN/tnsnames.ora
```

Note the exact `SERVICE_NAME` value.

### 3. Instance parameters

```sql
SHOW PARAMETER service_names
SHOW PARAMETER db_domain
SHOW PARAMETER local_listener

SELECT name FROM v$active_services;
SELECT name, open_mode FROM v$pdbs;
```

### 4. Force registration

```sql
ALTER SYSTEM REGISTER;
```

Wait 5 seconds, re-check `lsnrctl services`.

## Common Fixes

### Wrong SERVICE_NAME

Match exactly (case-insensitive, but match db_domain suffix):

Instance side:

```sql
SHOW PARAMETER service_names
-- Might show: prod.corp.example.com
```

Client:

```
SERVICE_NAME = prod.corp.example.com
```

### PDB closed

```sql
ALTER PLUGGABLE DATABASE hrpdb OPEN;
-- Then the pdb name service registers automatically
ALTER SYSTEM REGISTER;
```

Persist the state:

```sql
ALTER PLUGGABLE DATABASE hrpdb SAVE STATE;
```

### RAC service not started

```bash
srvctl status service -db prod -service reports
srvctl start service -db prod -service reports
srvctl status service -db prod -service reports
```

### Wrong local_listener

Instance registering with a different listener than the client is connecting to.

```sql
SHOW PARAMETER local_listener
ALTER SYSTEM SET local_listener = '(ADDRESS=(PROTOCOL=TCP)(HOST=dbhost)(PORT=1521))' SCOPE=BOTH;
ALTER SYSTEM REGISTER;
```

### db_domain suffix mismatch

If instance sets `db_domain = corp.example.com`, service name registered is `pdb.corp.example.com`. Client must include the domain.

## Best Practices

1. Use fully-qualified `SERVICE_NAME` including `db_domain`.
2. `ALTER PLUGGABLE DATABASE ... SAVE STATE;` for PDBs — auto-open on restart.
3. Standardize on SCAN listener in RAC.
4. Alert on services disappearing from `V$ACTIVE_SERVICES`.
5. In multitenant, PDB service names match PDB names — don't try to hijack.
6. After every restart, verify `lsnrctl services`.

## Interview Questions

1. **Q:** `ORA-12514` vs `ORA-12505`?
   **A:** 12514 = SERVICE unknown. 12505 = SID unknown.

2. **Q:** Common causes?
   **A:** Wrong service name, instance not registered, PDB closed.

3. **Q:** How do you force registration?
   **A:** `ALTER SYSTEM REGISTER;`.

4. **Q:** How to prevent PDB service loss on restart?
   **A:** `ALTER PLUGGABLE DATABASE ... SAVE STATE;` after opening.

5. **Q:** In RAC, why might a service fail to register?
   **A:** Service not started (`srvctl start service`), preferred/available assignment excludes this instance.
