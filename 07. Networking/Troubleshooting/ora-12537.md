# ORA-12537: TNS: connection closed

## Overview

The peer (usually the server) closed the socket unexpectedly during connect or session. Signals that the connection reached the listener but was terminated abruptly.

## Common Causes

1. **Firewall dropping idle or long connections.**
2. **Server process crashed** (e.g., `ORA-07445`, `ORA-00600`).
3. **Instance shutting down** during connect.
4. **Handshake timeout** — `SQLNET.INBOUND_CONNECT_TIMEOUT` fired.
5. **`SQLNET.EXPIRE_TIME` killed a dead session.**
6. **Missing or wrong protocol adapter.**
7. **Client-server version incompatibility** (very old client).
8. **SELinux blocking listener → foreground fork/exec.**

## Diagnostic Steps

### 1. Server alert log

```bash
tail -100 $ORACLE_BASE/diag/rdbms/<db>/<inst>/trace/alert_<sid>.log
```

Look for `ORA-`, `KILLED`, or crash messages timestamps around the failure.

### 2. Listener log

```bash
tail -200 $ORACLE_BASE/diag/tnslsnr/<host>/<listener>/alert/log.xml
# or
tail -200 $ORACLE_BASE/diag/tnslsnr/<host>/<listener>/trace/listener.log
```

Successful `establish` but immediate `disconnect` = server killed the connection.

### 3. Client trace

Enable client trace:

```
# sqlnet.ora on client
TRACE_LEVEL_CLIENT = SUPPORT
TRACE_DIRECTORY_CLIENT = /tmp
```

Retry, examine trace file.

### 4. Server-side timeouts

```
# sqlnet.ora on server
SQLNET.INBOUND_CONNECT_TIMEOUT = 60
```

Check log for `WARNING: inbound connection timed out`.

### 5. Network path

```bash
# From client
telnet dbhost 1521
mtr --tcp -P 1521 dbhost      # trace + latency
```

## Common Fixes

### SELinux blocking

Check `/var/log/audit/audit.log` for denials. Adjust policy or set enforcement to permissive during testing.

### Firewall aborting

- Firewall's stateful table dropping idle connections.
- Fix: `SQLNET.EXPIRE_TIME = 10` on server side + TCP keepalive.
- Or add exemption for Oracle connections.

### Server process crashed

Investigate the specific `ORA-00600` / `ORA-07445` — engage Oracle Support with trace file.

### Handshake timeout

Increase `SQLNET.INBOUND_CONNECT_TIMEOUT` (default 60s) if legitimate.

### Client protocol version mismatch

Upgrade client to at least the same major version as server, or use `SQLNET.ALLOWED_LOGON_VERSION_SERVER = 11` to allow older auth.

## Best Practices

1. Enable `SQLNET.EXPIRE_TIME = 10` to prevent firewall drops.
2. Enable TCP keepalive at OS level (`net.ipv4.tcp_keepalive_time`).
3. Monitor alert log — repeated ORA-12537 from same client = client bug or network issue.
4. Trace both client and server for one bad session — root cause is usually obvious in the traces.
5. If firewall is unavoidable, set both `SQLNET.EXPIRE_TIME` and OS keepalive to sub-firewall-timeout.

## Interview Questions

1. **Q:** `ORA-12537` — what happened?
   **A:** Peer closed the socket. Usually server killed the connection due to crash, timeout, or firewall.

2. **Q:** First diagnostic step?
   **A:** Server alert log + listener log for the exact time.

3. **Q:** Firewall issue — how to detect?
   **A:** Connection works for a while then errors after idle period; log shows session vanishing without alert log message.

4. **Q:** Fix for firewall dropping idle sessions?
   **A:** `SQLNET.EXPIRE_TIME = 10` + TCP keepalive.
