# ORA-12541: TNS: no listener

## Overview

Client reached the target host but nothing was listening on the specified port. The most common Oracle networking error along with `ORA-12154`.

## Common Causes

1. **Listener not running.**
2. **Wrong port** in connect string.
3. **Wrong host** in connect string.
4. **Firewall dropping SYN to port 1521**.
5. **Listener bound to different interface** than client's route.
6. **Listener starting up** (transient).

## Diagnostic Steps

### 1. From client, TCP test

```bash
# Linux
telnet dbhost 1521
nc -v dbhost 1521

# Windows
Test-NetConnection -ComputerName dbhost -Port 1521
```

**Connection refused** → nothing listening / firewall.

**Timeout** → firewall drop or wrong host.

### 2. Server-side

```bash
lsnrctl status
netstat -tlnp | grep 1521   # or ss -tlnp
```

If `lsnrctl status` errors, listener is not running.

### 3. Verify connect string

Alias:

```
PROD =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL=TCP)(HOST = dbhost.example.com)(PORT = 1521))
    ...)
```

Verify HOST resolves:

```bash
nslookup dbhost.example.com
dig dbhost.example.com
```

Verify PORT: 1521 (default) or non-default.

## Common Fixes

### Start the listener

```bash
lsnrctl start LISTENER
```

In RAC:

```bash
srvctl start listener -n <node>
```

### Wrong host/port in tnsnames.ora

Fix and reload client. `tnsnames.ora` changes apply on next connect (no reload needed).

### Firewall

- Ask network team to open TCP 1521 from client subnet to DB host.
- Or use `iptables`/`firewalld` on DB host.

### Listener bound to wrong interface

`listener.ora` `HOST = 0.0.0.0` binds all interfaces. `HOST = 10.0.1.5` binds only that IP.

## Best Practices

1. Alert on listener process not running (`process oracle_listener` check).
2. Standardize port 1521.
3. Use SCAN in RAC — one name resolves to all listeners.
4. Automate listener start via `srvctl` or systemd on single-instance.
5. Firewall exemptions between app tier and DB tier documented and reviewed.

## Interview Questions

1. **Q:** `ORA-12541` — where is the problem?
   **A:** Client reached host but nothing listening on target port. Listener down or firewall/network issue.

2. **Q:** How do you confirm?
   **A:** `telnet dbhost 1521` — connection refused = listener down; timeout = firewall.

3. **Q:** Immediate fix?
   **A:** `lsnrctl start`.

4. **Q:** RAC — how do you manage listener startup?
   **A:** `srvctl start listener -n <node>`; ideally CRS auto-restarts.
