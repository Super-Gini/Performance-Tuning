# SQL Profiles

## Overview

A **SQL Profile** is a set of statistics-adjusting hints stored with a SQL statement. Unlike a **baseline**, which locks a plan, a profile **nudges** the optimizer with better cardinality corrections. CBO can still pick a different plan later if data changes — profiles are advisory.

SQL Profiles are generated by **SQL Tuning Advisor** (part of the Tuning Pack) or `DBMS_SQLTUNE.IMPORT_SQL_PROFILE`. Requires **Tuning Pack** license.

## Difference vs Baseline

|                              | SQL Profile                | Baseline                 |
| ---------------------------- | -------------------------- | ------------------------ |
| Purpose                      | Correct CBO cost           | Lock a plan              |
| Content                      | Adjusted cardinality hints | Full plan                |
| CBO can pick different plan? | Yes                        | No (must match accepted) |
| License                      | Tuning Pack                | EE (no separate license) |
| Generated by                 | SQL Tuning Advisor         | Manual or capture        |
| Multiple profiles per SQL    | No (one)                   | Yes (multiple baselines) |

**In practice**: use baselines for known-good plans; use profiles for CBO's cardinality corrections when you want CBO to keep choosing.

## Creation via SQL Tuning Advisor

```sql
DECLARE
  task_name VARCHAR2(30);
BEGIN
  task_name := DBMS_SQLTUNE.CREATE_TUNING_TASK(
    sql_id => '&sql_id',
    scope => DBMS_SQLTUNE.SCOPE_COMPREHENSIVE,
    time_limit => 3600,
    task_name => 'TUNE_&sql_id');

  DBMS_SQLTUNE.EXECUTE_TUNING_TASK('TUNE_&sql_id');

  DBMS_OUTPUT.PUT_LINE(DBMS_SQLTUNE.REPORT_TUNING_TASK('TUNE_&sql_id'));
END;
/

-- If advisor recommends a profile, accept it
BEGIN
  DBMS_SQLTUNE.ACCEPT_SQL_PROFILE(
    task_name => 'TUNE_&sql_id',
    replace => TRUE,
    force_match => FALSE);
END;
/
```

`FORCE_MATCH=TRUE` uses signature matching so the profile applies even with different literals in the SQL.

## Manual Import

Rare — usually for cross-DB profile migration:

```sql
DECLARE
  ar_hints SYS.SQLPROF_ATTR;
BEGIN
  ar_hints := SYS.SQLPROF_ATTR(
    'BEGIN_OUTLINE_DATA',
    'FULL(@"SEL$1" "T"@"SEL$1")',
    'END_OUTLINE_DATA');

  DBMS_SQLTUNE.IMPORT_SQL_PROFILE(
    sql_text => 'SELECT ... FROM t WHERE ...',
    profile => ar_hints,
    name => 'MY_PROFILE',
    force_match => TRUE);
END;
/
```

## Managing Profiles

```sql
-- List
SELECT category, name, sql_text, status,
       force_matching_signature, last_modified
FROM   dba_sql_profiles;

-- Disable / enable
BEGIN
  DBMS_SQLTUNE.ALTER_SQL_PROFILE(
    name => 'MY_PROFILE',
    attribute_name => 'STATUS',
    value => 'DISABLED');
END;
/

-- Drop
BEGIN
  DBMS_SQLTUNE.DROP_SQL_PROFILE(name => 'MY_PROFILE');
END;
/
```

## Diagnostic Queries

```sql
-- Profiles in use in cursor cache
SELECT sql_id, sql_profile, plan_hash_value
FROM   v$sql
WHERE  sql_profile IS NOT NULL;

-- All profiles
SELECT name, category, status, force_matching_signature, created
FROM   dba_sql_profiles
ORDER  BY created DESC;

-- SQL Tuning Advisor tasks
SELECT owner, task_name, status, execution_start, execution_end
FROM   dba_advisor_tasks
WHERE  advisor_name = 'SQL Tuning Advisor'
ORDER  BY execution_start DESC;
```

## Automatic SQL Tuning Task

Runs during maintenance windows; captures high-load SQL and generates recommendations:

```sql
SELECT client_name, status FROM dba_autotask_client
WHERE  client_name = 'sql tuning advisor';

-- View recent recommendations
SELECT task_name, execution_start,
       DBMS_SQLTUNE.REPORT_AUTO_TUNING_TASK(NULL) AS report
FROM   dual;
```

Auto-implementation of profiles from the auto task is off by default. Enable per policy:

```sql
BEGIN
  DBMS_AUTO_SQLTUNE.SET_AUTO_TUNING_TASK_PARAMETER(
    'ACCEPT_SQL_PROFILES', 'TRUE');
END;
/
```

## Common Issues

- **Profile not used** — SQL text signature changed (whitespace, literals). Recreate with `FORCE_MATCH`.
- **Profile makes plan worse** — Rare, but disable and re-run tuning advisor.
- **License scare** — Do not accept profiles from auto tuning without Tuning Pack license.
- **Profile suppresses new better plan** — Drop and re-tune.

## Best Practices

1. Use SQL Tuning Advisor for **high-impact** SQL, not routine work.
2. `FORCE_MATCH=TRUE` for SQL with literals.
3. Review advisor recommendations before accepting.
4. Do not blindly enable `ACCEPT_SQL_PROFILES` in auto task.
5. Prefer **baselines** for pinning plans; use profiles for cardinality nudges.
6. Backup profiles with `PACK_STGTAB_SQLPROF` before major changes.
7. Do not run Tuning Advisor without Tuning Pack license.

## Interview Questions

1. **Q:** What is a SQL Profile?
   **A:** Statistics-adjusting hints stored with a SQL to help CBO produce better plans. Generated by SQL Tuning Advisor.

2. **Q:** Profile vs baseline?
   **A:** Profile nudges CBO cost (CBO still chooses); baseline locks a plan.

3. **Q:** License?
   **A:** Tuning Pack.

4. **Q:** `FORCE_MATCH`?
   **A:** Match by SQL signature ignoring literals — profile applies to structurally identical statements.

5. **Q:** How do you view profiles?
   **A:** `DBA_SQL_PROFILES`.

6. **Q:** Automatic SQL Tuning Task?
   **A:** Runs during maintenance windows; generates recommendations. Auto-accepting profiles is off by default.
